# Web Content Accessibility Guidelines (WCAG) 2.2

## Reference

Alastair Campbell, Chuck Adams, Rachael Bradley Montgomery, Michael Cooper,
and Andrew Kirkpatrick, editors. “[Web Content Accessibility Guidelines (WCAG)
2.2](https://www.w3.org/TR/2024/REC-WCAG22-20241212/).” W3C Recommendation,
12 December 2024.

## Contribution

WCAG 2.2 supplies technology-neutral, testable success criteria for making web
content perceivable, operable, understandable, and robust for people with a
wide range of disabilities. It is used here as evidence of a modern systematic
accessibility discipline absent from early Smalltalk descriptions.

## Method

The standard organizes normative success criteria by conformance level and
connects them to non-normative techniques, understanding documents, and an
implementation report. It is a web-content standard, not a complete desktop
window-system or operating-system UI specification.

## Findings

- Information and relationships need machine-readable equivalents rather than
  being communicated only by pixels, color, or spatial layout.
- Functionality must remain operable from a keyboard and expose predictable
  focus behavior.
- Text alternatives, captions, contrast, reflow, target size, timing, error
  identification, and consistent interaction are explicit test areas.
- Compatibility with user agents and assistive technology requires names,
  roles, values, states, and change notifications to remain programmatically
  available.
- Conformance does not address every possible disability need and does not by
  itself establish usability.

## Relevance

Kay's inclusive educational ambition did not specify today's accessibility
contract. Atom OS should make semantic roles, relationships, actions, focus,
and state a primary part of the UI protocol so assistive technology and
automation do not have to infer meaning from rendered surfaces.

## Limits

WCAG targets web content and must be adapted carefully to desktop and immersive
interfaces. It says little about compositor trust, application isolation,
actor recovery, or end-user programming.
